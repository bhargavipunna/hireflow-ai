## Phase 1 Plan — Core Foundation + All Agents

Goal: transform the MVP into a properly-architected, runnable system with the full agent set, repo layer, logging, error handling, retry, and config-driven scrapers. Scheduler + FastAPI + deep real scraping = Phase 2.

All chosen constraints honored:
- requests + BeautifulSoup + retry (no Playwright)
- Outbound actions (cold email, apply) = **draft only, never send**
- Persistence = **JSON via repository layer** (no new DB deps)

---

### A. Foundation & Infrastructure (new)

1. **`app/config/settings.py`** — expand to hold all config with safe defaults: paths (`DATA_DIR`, `LOG_DIR`, generated-output dirs), matching threshold (`MATCH_THRESHOLD`), top-K, model name, scheduler/email placeholders, scraper timeouts/retries. Keep env-driven.
2. **`app/config/logger.py`** — centralized logging: console + rotating file under `logs/`. Expose `get_logger(name)`. Replace `print()` calls in agents with loggers.
3. **`app/config/exceptions.py`** — `ScraperError`, `LLMServiceError`, `EmbeddingError`, `RetrievalError`, `ConfigError`.
4. **`app/utils/http_client.py`** — `HTTPClient` using `requests` + `tenacity` retry (exp backoff), rotating User-Agent pool (expand `utils.py`'s tiny list), timeout, graceful failure returning `None`. One shared instance.
5. **`app/utils/retry.py`** — thin wrappers / decorators for reuse.

### B. Models (enhance + add)

6. **`app/models/job.py`** — keep dataclass, add `id`, `to_dict()`, `from_dict()`, normalize whitespace.
7. **`app/models/application.py`** — `Application` (job_id, company, title, status, applied_at, resume_path, cover_letter_path, email_path, score).
8. **`app/models/generated_doc.py`** — `GeneratedDocument` (type, job_ref, path, created_at).

### C. Repository Layer (new)

Replace direct `json.dump`/`open()` in agents with these repos.

### E. Agents (add the missing ones + fixes)

19. **`app/agents/cover_letter_agent.py`** — `CoverLetterAgent`: generate tailored cover letter for jobs above threshold (Qwen3 via LLMService), save to `data/cover_letters/`, record in repo.
20. **`app/agents/ats_scorer_agent.py`** — `ATSScorerAgent`: LLM-based keyword-coverage + structure scoring on generated resume vs job; attach ATS score to matched job.
21. **`app/agents/recruiter_agent.py`** — `RecruiterAgent`: infer likely recruiter name/email pattern from company domain (deterministic, no scraping of people); store on job.
22. **`app/agents/cold_email_agent.py`** — `ColdEmailAgent`: generate personalized cold email **draft** to file (`data/emails/`), never sends. Includes subject + body.
23. **`app/agents/tracker_agent.py`** — `TrackerAgent`: upsert each high-score job into `ApplicationRepository` with status pipeline (`discovered → matched → resume_generated → applied_draft → reported`).
24. **`app/agents/daily_report_agent.py`** — `DailyReportAgent`: produce `reports/report_YYYY-MM-DD.md` summarizing jobs found, top matches, resumes/letters/emails drafted, tracker counts.
25. **Fix `app/rag/retriever.py`** — remove the duplicate `retrieve()` method.
26. **`app/agents/resume_agent.py`** — keep current edits, refactor to use repos + logger, attach generated-doc record, only generate above threshold.

### What is explicitly OUT of Phase 1 (→ Phase 2)
- APScheduler daily cron + daemon mode
- FastAPI REST API / dashboard endpoints
- Real auto-apply form submission (Playwright)
- Deep per-site real scraping beyond graceful-fetch + JSON-LD/BS4 parsing
- Real SMTP email sending (stays draft-only now and likely always, behind a flag)

### How I'll keep it runnable
- Every new agent is wired but threshold-gated, so a dry run still produces the existing sample-data output plus new artifacts.
- No required new heavy deps; `tenacity`/`aiohttp` only.
- Logging replaces prints so output stays readable.
- I will NOT attempt `pip install` inside the sandbox if it's restricted; I'll add to `requirements.txt` and note the install step for you.
